## 결정 1 — 학생 서비스 접근 방식

**결정**: 학생은 **(a) CCC 로그인** 또는 **(b) 간사가 공유한 고유 링크** 둘 다로 진입할 수 있고, 어느 쪽이든 같은 예약 페이지로 도착한다.

- **미신청자** → "타지구 버스 신청한 사람만 이용 가능"이라는 안내 화면을 보여준다.
- **신청자** → 본인 예약 페이지(`/me`)로 바로 이동.
- **링크의 고유번호 = 우리 시스템이 발급**(예약번호 `BUS-XXXX`). 학생은 번호를 **타이핑하지 않고**, 링크 진입 후 **본인 이름 + 전화 끝 4자리**로 본인 확인 (SPEC §3.S5).
- **취소 등 되돌리기 어려운 행동** = 본인 **전화번호 전체 입력** 게이트.
- **무차별 대입 잠금(rate-limit)은 두지 않기로 판단.** 입구가 CCC·QR·고유링크라 "전화 끝 4자리 추측"으로 들어올 문 자체가 없기 때문. 단 **링크·토큰은 개인별·무작위**여야 함.
- **하행 QR**: 이름표의 QR은 우리 특정 웹페이지로 **연결만** 한다(별도 신원 정보 전달 없음 → 우리가 QR에서 받아올 데이터는 없음).

**배경/근거**: 학생은 본인 차편·좌석·채팅만 확인하는 저빈도 사용자. 진입 마찰을 줄이되(링크/QR/CCC), 개인정보 보호는 "보기=본인확인 통과 / 취소=전화 전체"로 단계화. 이름표는 공개 노출이라 QR 단독 풀로그인은 지양.

**영향**: 학생 화면·진입 분기(미신청/신청) = **팀원2** 영역. 세션·로그아웃 primitive는 팀장/CC가 이미 제공(`lib/auth/passenger*`, `lib/auth/logout.ts`).

## 결정 2 — Trip "학생담당연락처(총무)" 필드 추가

**결정**: `trips` 테이블에 **총무(학생 담당) 연락처 컬럼을 추가**한다(예: `manager_phone`).

- 스키마 변경 = **core(마이그레이션) → 팀장 소관** + 타입 재생성 동반.
- **작업 분담**: 급하면 **팀장이 차량 등록 페이지를 직접 구현**. 팀원1이 만들면 **팀장이 리뷰 후 총무 연락처 필드만 따로 추가**한다.

**배경**: 간사 요청 — 차량 등록 페이지에 차량기본정보·집합지·요금·담당간사연락처와 함께 **학생담당연락처(총무)**가 필요. 현 스키마엔 전용 필드가 없고 메모(500자)만 있음(SPEC §5.4). 담당간사 연락처는 간사 가입 시 등록 전화로 커버됨.

**재검토**: 등록 폼 구현 착수 시(컬럼명·필수여부 확정).

## 결정 3 — 차량등록·타지구신청 페이지 우선 구현 + 역할

**결정**: 간사 요청(차량 등록 페이지 + 타지구 신청 예시 페이지)을 **우선 구현**한다. 이는 `TEAM-TASKS §2`의 **팀원1 작업 #2(`/operator/trips`·`/trips/new`)·#5(`/operator/requests`·`/requests/new`)와 동일**하므로 **팀원1에게 우선순위로 배정**한다.

- 현재 해당 라우트는 Placeholder(빈 화면), `lib/matching/`은 빈 폴더 — 새로 구현 필요.
- 급하면 팀장이 맡되, **팀원1과 명시적으로 조율**(같은 파일 중복 작업 금지).
- 참조: SPEC §5.4(등록 폼)·§5.6(신청), `requireOperator()`(`lib/auth/operator.ts`), 집합지 드롭다운용 `region_locations` seed.

## 결정 4 — 학생 세션(JWT)은 우리 구현 기준 (팀원2 버전 비교 X)

**결정**: 학생 세션·JWT 관련은 **우리가 올린 `lib/auth/passenger-session.ts`·`passenger.ts`·`logout.ts` 기준**으로 진행한다. 팀원2가 테스트로 만든 별도 세션 구현과는 **비교·병합하지 않는다**(우리 버전이 정본).

- 팀원2는 학생 *페이지*에서 우리 헬퍼(`issuePassengerSession`·`requirePassenger`·`logoutPassenger`)를 **호출만** 한다.
- 근거: operator·master와 동일 패턴 + Vitest 통과 + auth 인프라(팀장/CC) 영역의 올바른 위치. 두 구현을 합치는 비용보다 일원화가 명확.

**재검토**: 없음 (확정).
