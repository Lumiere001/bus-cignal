## CCC가 회신한 흐름 (확정)

여름수련회 사이트 `[전국 버스 잔여석 신청]` 메뉴 →
1. `[간사입니다]` → **CCC 로그인**으로 리다이렉트
2. 로그인 성공 → CCC가 **1회용 코드 발급(TTL 5분)**
3. `?code=XXXX`로 **우리 버스사이트 리다이렉트**
4. 우리가 **검증 API로 코드 검증** → 신원 수신: **간사번호 · 이름 · 전화번호 · 지구코드 · 지구명**
5. 그 신원으로 **본인 지구 버스 관리 시작**

- **학생은 CCC 로그인 불필요** — 간사가 발급(예약번호·매직링크)하는 우리 방식 유지.
- 평문 신원이 URL에 실리지 않음(코드 → 서버-서버 API 검증) = 안전.
- CCC측 **코드검증 API는 주말 중 제공 예정**.

## 결정 1 — 마스터 승인 단계 제거 (자동 프로비저닝)

CCC가 신원+지구를 검증해 넘겨주므로, "진짜 간사인지" 확인 목적의 **마스터 승인은 불필요**.
- **CCC 로그인 성공 시 operator를 자동 생성/갱신(approved) → 바로 본인 지구로 입장.**
- 한 지구에 간사가 여러 명이어도 모두 입장해 협업. **"차량 담당" 구분은 하지 않기로 함**(간사님께 묻지 않음) — 신뢰 기반 + 마스터 회수 안전망으로 충분.
- **마스터 역할 = 운영 조종석**(승인기 아님): 전국 관전(대시보드·매칭·정산 매트릭스)·시스템 설정(마감일·점검·익명화)·**긴급 비활성화(revoke)**·분쟁 조정.

## 결정 2 — 지구 매핑

CCC의 **지구코드 ↔ 우리 regions** 매핑이 필요. CCC에 **지구코드 표(코드↔지구명)** 요청. 우리 `regions`(전국)와 코드/이름으로 매핑.

## 우리가 만들 것 (consumer — API 도착 후)

- **콜백 라우트** `/login?code=XXXX`: 세션 없을 때 코드 수신 → CCC 검증 API 호출(서버-서버) → 신원 수신 → 지구코드로 region 매핑 → **operator upsert(approved, region, ccc_id=간사번호)** → `signOperatorToken` 세션 발급 → `/operator`.
- 식별 앵커는 **우리 내부 `operators.id`**(세션·채팅 등)에서 사용. CCC 간사번호(`ccc_id`)는 신원 매핑 키로만.
- **매직링크(`2026-06-05-operator-magic-link-interim-login.md`)는 백업/임시로 유지** — CCC 경로가 정식이 되면 보조 또는 제거 결정.

## 우리가 CCC에 미리 준 것

- **콜백 주소**: `https://bus-cignal.vercel.app/login` (+`?code=`)
- **지구코드 표 요청** (위 결정 2)
- 나머지(응답 필드·API 인증 방식 등)는 **CCC가 만든 걸 받아 우리가 맞춤** — 선(先) 스펙 강요 안 함(협업·일정 동일).

## 보류 (API 수신 시 확정)

- 검증 API 명세: 엔드포인트·요청/응답 형식·**우리가 호출할 때 인증 방법**.
- 코드 1회용·5분 TTL의 CCC측 보장(재사용 차단) 확인.
- 지구코드 표 수령 → 매핑 테이블.
